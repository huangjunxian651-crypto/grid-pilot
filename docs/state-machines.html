0一句话心智模型：三层

理解这套系统先记住它分三层，每层是不同寿命的东西、各有自己的状态机。你的大部分困惑都来自把这三层混为一谈。

① Robot（机器人）— 长期实体，从创建到删除/归档
"我要在 币安 的 ETH/USDT 上做多网格" 这件事本身。管它的代码：BotManagerService
PAUSEDRUNNINGSTOPPINGSTOPPED
② Run / session（交易回合）— 临时，几分钟到几小时
价格进入某箱体"激活窗口"才诞生一个 Run，止盈/止损/用户停止就结束。一个 Robot 一生经历很多个 Run。落库的"账本状态"。

③ GridBotRunner + FSM（执行引擎）— 与 Run 同生死
真正在交易所挂单/撤单/平仓的内存对象，内部一个有限状态机逐 tick 决策。管它的代码：TradingEngineService + GridBotRunner

1Robot.status — 机器人状态机

你在列表/详情页看到的状态。要点：RUNNING ≠ 正在交易（含"监控中"：无活跃箱、调度器在等价格进窗）；STOPPING 是异步停止新增的中间态，绝不卡死，出错也兜底落 STOPPED。

点击上方任意状态查看其迁移与触发条件。

2Run.state — 交易回合状态机

数据库里每条 Run 记录的状态。与 ③ 的 FSM 高度重叠但不完全相同——Run.state 是落库的账本状态，FSM 是内存的执行状态。四个终态会写 endedAt。非终态跟随 FSM 写回（syncRunStateFromFsm）：恢复时按真实持仓落 RUNNING（有仓）或 TRAILING_ENTRY（无仓），上层不硬猜。

点击上方任意状态查看其迁移与触发条件。

3FSM.kind — 执行引擎内部状态机

最底层、最细的状态机，在 GridBotRunner 内驱动每一次行情 tick 的决策。三个终态 TAKE_PROFIT / LIQUIDATED / CANCELLED 一旦进入，runner 自动停止、回合结束。

点击上方任意状态查看其迁移与触发条件。

4三层怎么联动

⬇ 用户操作：自上而下传

Robot 停止 → 调 session 级 stopBot/detachBot → runner 内 FSM 走向终态 → 终态回调 handleAutoTermination → 写 Run.state 终态 → 通知 Robot 清掉活跃箱。
Robot: STOPPING → FSM: LIQUIDATING→LIQUIDATED → Run: STOPPED → Robot: STOPPED

⬆ 自动事件：自下而上冒

价格触发止盈/止损 → FSM 进终态 → 写 Run 终态（endedAt）→ 回调 onBoxTerminated 清活跃箱 → Robot 回到 RUNNING 的"监控中"等下一次激活。
FSM: RUNNING→TAKE_PROFIT → Run: TAKE_PROFIT → Robot: RUNNING（监控中）

6停止流程（stopStage / stopWarning）

用户点"停止"后，后台 runStopJob 分阶段推进，每阶段把进度写进 robot.stopStage 供前端轮询显示。点击下方阶段查看。

若过程不干净，落 STOPPED 时带一个 stopWarning（前端翻译成提示，不卡死）

stopWarning含义
LIQUIDATION_TIMEOUT平仓 30 秒没完成，交易所可能还有仓，去核对
RESIDUAL_POSITION复核后仍有残留、强平也失败，去手动平
SNAPSHOT_UNAVAILABLE抓快照失败，停止前持仓数据可能不全
STOP_INTERRUPTED停止过程被意外打断（兜底），去核对仓位与挂单
