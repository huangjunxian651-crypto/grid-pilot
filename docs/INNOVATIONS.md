## 1. 先观察后决策的「盯盘」思维

**交易所网格的缺陷**：把所有买卖单一次性挂入交易所，订单挂出后不再移动，被动等市场来撞单。市场不来，就一直挂着；价位不利，照样成交。

**我们的做法**：像人类交易员盯盘一样，**每次收到行情更新先观察、再决策**——是否挂单、挂什么价、还是撤掉旧单。

**技术细节**：系统是事件驱动的。每个行情 tick 都重新判断当前价与网格目标价的关系：
- 条件不利（价格比目标买价更贵，落入「熔断区」）→ 拒绝下单 / 撤掉现有挂单，观望；
- 条件有利（落入「POC 区」）→ 在当前最优买价挂 Post-Only 单卡位；
- 价格大幅偏离（落入「GTC 区」）→ 改为主动吃单，锁定超额价差。

因此 **GridPilot 在任意时刻不一定有网格单挂着**——这与交易所网格「始终满屏挂单」截然相反。本质是在基础网格上叠加了一层**自动化盯盘决策**。

**价值**：以当前市场最优价卡位，而非等市场撞预设静态单；不利时主动停手，避免错误价位成交；价格跳跃时能吃到超出网格步长的额外价差。

## 2. Maker 优先 / Taker 特许 / 不利熔断：三区间动态定价

**交易所网格的缺陷**：不区分主动/被动成交，常以 Taker 身份吃单。而在杠杆与高频网格下，手续费是最大的隐性成本——Taker（≈0.05%）几乎吃尽网格步长（≈0.1%）的利润。

**我们的做法**：每次下单按「当前价 vs 网格目标价」的偏离度，动态选择三种方式之一。

| 区间 | 触发条件 | 下单方式 | 手续费 | 经济合理性 |
|------|---------|---------|--------|-----------|
| **熔断区** | 价格方向不利 | 不下单 | 0 | 没有基本利润保障，不交易 |
| **POC 区** | 偏离 < 阈值 | Post-Only 挂在买一/卖一价 | **0.02%（Maker）** | 默认首选，以 Maker 身份卡位 |
| **GTC 区** | 偏离 ≥ 阈值 | 市价吃单 | 0.05%（Taker） | 额外价差 > 多付的 0.03%，划算 |

**期望值证明（为什么坚持 Maker）**：以 Gate.io 为例（Maker 0.02% / Taker 0.05% / 步长≈0.1%）：

```
Taker 双侧成交（100% 填单）：净利润 = 0.1% − 0.05%×2 = 0%      ← 手续费吃尽步长利润
Maker 双侧成交（设 50% 循环完成率）：每轮 0.1% − 0.02%×2 = 0.06%
                                   期望 = 50% × 0.06% = 0.03% > 0%
```

> **结论**：只要循环完成概率 > 0，Maker 的期望利润就高于 Taker——因为 Taker 每轮净利润本已为零，任何 Maker 成交都是净增益。

**GTC 的经济模型**：GTC 阈值默认 0.1%，= `ExcessProfitMultiplier(2.0) × takerFee(0.05%)`，约为「划算最小阈值」(takerFee − makerFee = 0.03%) 的 3.3 倍，保守留足余量。只有当额外价差利润确实超过多付的手续费，才特许吃单。

**价值**：默认每笔约省 0.03% 手续费；只在真正划算时才主动吃单锁定超额利润；不利时一分不花。Maker 负责低成本常规成交、GTC 负责大偏差超额利润，两者互补覆盖全部有利场景。

## 3. 追逐下单：实时定价与订单追踪

**交易所网格的缺陷**：挂在固定网格理论价，价格没到就一直空等，价格掠过也未必成交。

**我们的做法**：不等价格跌到理论价才下单，而是**追着买一/卖一价反复预挂**，力争 Maker 成交或大偏差时吃单。

**技术细节**：
- **挂在买一/卖一价**：POC 单的价格 ≠ 网格理论价，而是当前 `bestBid`（买入）/`bestAsk`（卖出）——等于自己成为当前最优盘口，下一笔市价单进来即以 Maker 成交，且成交价比理论价更优（额外收益）。
- **追踪改单**：每个 tick 检查——① POC→GTC 升级（机会稍纵即逝优先吃）；② 盘口偏移超过 `当前价×0.02%` 改单阈值则撤单重挂保持最优竞价；③ 进入熔断区则撤单观望。
- **执行串行化**：任意时刻最多一个活跃网格单 Pending；订单成交/撤销事件本身也触发「重算目标仓位 → 追逐下单」，不等下一 tick，避免错过最优时机。
- **止损优先**：一旦进入止损流程，立即放弃所有进行中的网格下单，确保不再开新仓。

**价值**：把「等价格来」变成「追着最优价去」，最大化 Maker 成交率与成交价优势。

## 4. 追踪建仓：不预测最低点，只确认离开最低点

**交易所网格的缺陷**：价格一进区间就立即开仓，常常「一建仓就站在高位被套」，下跌途中越买越亏。

**我们的做法**：价格从上方落入区间时**不立即开仓**，先追踪亏损端极值，等价格从极值反弹确认幅度（`TrailingCallbackRate`，默认 0.2%）后才建仓。

**技术细节**：
- 追踪极值（做多取低点 / 做空取高点），触发价 = `极值 × (1 ± 回调率)`，反弹达标即进入 RUNNING。
- 若价格继续越过激活价（更靠止盈端）→ 追踪窗口关闭，回到监听；若越过满仓线 → 直接走止损流程。
- **巧思**：若价格是**朝止盈方向**反向进入区间（亏损端已在身后），则**跳过追踪、直接 RUNNING**——此时入场成本更靠近清算端，每格平仓利润更高，等待反而错失收益。

**价值**：本质是「不预测最低点，只确认已经离开最低点」。无论跌到哪里，只要确认反弹就安全建仓，规避顶部接盘。

## 5. 多段价格区间：价格去哪里，策略就跟到哪里

**交易所网格的缺陷**：固定单一区间，价格走出区间就失效或满仓被套。

**我们的做法**：预配置多个**不重叠**的价格区间（箱体），由「区间管理器」实时监控价格，价格进入哪段就激活哪段，其余休眠。

**技术细节**：
- **单 runner 不变量**：任意时刻最多一个区间的机器人运行；管理器持续监听，负责激活/停止/重激活。
- **激活窗口**：仅当 `activationPrice` 与清算线之间（靠亏损端）才激活——靠止盈端启动则止盈空间小、亏损风险大，期望值为负。
- **方向感知**：朝亏损方向进入用追踪建仓；朝止盈方向进入直接 RUNNING。
- **异常恢复**：崩溃重启后若仍有持仓，跳过追踪建仓直接 RUNNING 接管；启动先清理上一轮遗留算法单，避免新旧两套条件单重叠误触发。

**价值**：面对宽幅震荡的标的，策略始终跟随价格落到的区间运作，而非被单一区间锁死。

## 6. 箱体几何与 d 空间单实现：做多/做空一套代码

**普遍工程缺陷**：多数实现把做多/做空写成两套镜像逻辑，分支多、易出错、难维护。

**我们的做法**：几何计算在归一化的 **d 空间**（离止盈端的有向距离，亏损方向为正）进行，方向分支**只出现在两个映射函数里**：

```
LONG:  d = takeProfitPrice − price
SHORT: d = price − takeProfitPrice
```

区域判定、目标仓位、激活窗口、追踪建仓、FSM 触发**全部在 d 空间单实现，做空自动镜像做多**。箱体锚定在**止盈端**，向亏损方向展开四条结构线：止盈线 → 主网格区 → 满仓线 → 隔离带 → 止损区起点 → 止损区 → 清算线。

**隔离带的经济动机（不只是缓冲）**：它是满仓线与止损区之间的「死区」，**防止价格在边界震荡时主网格加仓与止损减仓交替触发、反复付双边手续费**。短暂的价格噪声无法同时触发两套逻辑，大幅减少无效交易。

**价值**：一套代码覆盖多空、零镜像分支 = 更少 bug、更易审计；隔离带直接省下边界震荡的手续费损耗。

## 7. 状态无关的目标仓位算法：分布式自愈

**交易所网格/朴素实现的缺陷**：依赖本地维护的订单/仓位历史。网络抖动、部分成交、并发竞态、崩溃重启都会让本地状态与交易所实际持仓「对不上」，需要人工清理。

**我们的做法**：目标仓位**完全由当前价格决定，不依赖任何历史状态**。

```
目标仓位 = f(当前价格)                      ← 无状态推导
实际操作量 = 目标仓位 − 交易所最新实际持仓     ← 实时取用
```

**技术细节**：
- 每个 tick 只问「当前价格下应持有多少仓位」，再与**实时查询**的真实持仓对比、直接纠偏——不追溯历史、不维护本地订单簿。
- **持仓双保险**：被动接收持仓推送 + 每次成交后**主动拉取**一次最新持仓（两条 WS 通道可能不同步，主动拉取防止用旧持仓超买/超卖）。
- **非对称缓冲**：卖出以「应持仓位」为基准（更易触发，快锁利润），买入以「应买仓位」为基准（更严格，须偏离超一格），积累正向偏度。

**价值**：崩溃多久、断网几小时、甚至用户手动改了仓位——只要程序重启拿到当前价，立刻算出应有仓位并纠偏，**没有「状态脏了要手工清理」的运维负担**。这是把分布式系统的不一致性从根上绕过去。

## 8. 统一止损机制：分层减仓 + 反弹恢复

**交易所网格的缺陷**：止损常是单一价位一次性全平；短暂跌破又反弹时，已被清仓，只能重新建仓再付一轮手续费。

**我们的做法**：主网格下方设「止损缓冲区」，**分层递减减仓**而非一次砍光；且止损区与主网格**共用同一个仓位计算函数**，无需特殊的条件单维护逻辑。

**技术细节**：
- `computeTargetPosition(price, config)` 覆盖箱体所有区域（主网格/隔离带/止损区/越界），止损区内 `targetHoldSize` 随价格下跌递减，价格每跌一格触发一次减仓，无需特殊 ping-pong 翻转。
- **兜底条件单**：仅在清算线挂一个「全平」条件单作最后防线，防极端情况下动态下单失败（断网/交易所故障）。
- **反弹恢复**：若短暂跌破后反弹，残余仓位直接受益，省去重新建仓的手续费。
- **无止损模式**：`stopLossGridCount = 0` 时不设止损区，越界保持满仓硬扛（适合对区间有强信心的用户）。

**价值**：把「一次性止损」变成「平滑分层减仓 + 保留反弹恢复力」，减少滑点与无谓的重建仓成本。

## 9. 止盈即「自然做完」：以箱体配置代替止盈单

**交易所网格的缺陷**：止盈/止损是附加的独立订单，逻辑与网格割裂。

**我们的做法**：止盈不是硬平仓，而是让网格**自然做完**——价格朝止盈方向移动时网格持续平仓、仓位逐步清空，最后一格平掉、价格越过止盈线时，机器人识别任务自然完成而退出。

**技术细节**：止盈条件 = 「价格到达止盈端 且 持仓为零」。**主动止盈**只需调整 `takeProfitPrice` 让止盈线靠近当前价（做多调低/做空调高），网格在新止盈线附近平完最后一份即退出——相当于把止盈线当「动态止盈线」用。

**价值**：朝止盈方向每一格的利润都赚到，不提前放弃区间内利润；用一个配置项就能精确控制退出价，无需额外止盈单逻辑。

## 总览对照表

| 维度 | 交易所原生网格 | GridPilot |
|------|----------------|-----------|
| **下单思维** | 批量静态挂单，挂上不动等撞单 | 事件驱动盯盘，先观察再决策，任意时刻不一定有挂单 |
| **手续费** | 不分主被动，常吃单 | 三区间定价：POC 省 Maker 费 / GTC 锁超额 / 熔断拒单 |
| **下单价** | 固定网格理论价 | 追逐买一/卖一价，追踪改单保持最优竞价 |
| **建仓时机** | 进区间立即开仓 | 追踪建仓确认反弹，避免顶部被套 |
| **行情适应** | 固定单一区间 | 多段不重叠区间，价格进哪段激活哪段 |
| **多空实现** | 两套镜像逻辑 | d 空间单实现，做空自动镜像做多 |
| **一致性** | 依赖本地状态，易脏需人工清理 | 状态无关 + 实时持仓，崩溃/断网自愈 |
| **止损** | 单价位一次性全平 | 分层递减减仓 + 清算线兜底条件单 + 反弹恢复 |
| **止盈** | 独立止盈单 | 网格自然做完；调 takeProfitPrice 即动态止盈 |

> ⚠️ 网格交易并非稳赚：单边下跌仍会浮亏，杠杆放大风险。以上为策略设计，不构成投资建议。请先理解策略、用小资金或测试网充分验证。

## English Summary

Exchange-native grid bots are essentially *"place all orders at once, leave them static, wait to be hit."* GridPilot instead **emulates an experienced live trader in software** — continuously observing the market and deciding, on every tick, whether and how to place/amend/cancel orders. Key innovations:

1. **Observe-then-decide** — event-driven; not always resting orders on the book.
2. **Maker-first / Taker-when-worth-it / circuit-break** three-zone pricing — saves ~0.03%/fill; Maker's expected profit beats Taker because Taker's per-cycle net is ~0.
3. **Chase ordering** — quotes at best bid/ask, re-pegs to stay top-of-book, serialized execution.
4. **Trailing entry** — doesn't predict the bottom; confirms a rebound before entering, avoiding buying the top.
5. **Multi-zone ranges** — multiple non-overlapping boxes; one activates wherever price goes.
6. **d-space single implementation** — long/short share one codebase (short auto-mirrors long); the isolation band prevents fee-churn at boundaries.
7. **Stateless target-position algorithm** — position is a pure function of price; reconciles against live exchange position → self-heals across crashes/disconnects.
8. **Unified stop-loss** — tiered reduction (not one-shot) + a fallback conditional at liquidation + rebound recovery.
9. **Take-profit as "let the grid finish"** — adjust `takeProfitPrice` for a dynamic take-profit; no separate TP order.

See [`docs/STRATEGY_SPEC.md`](STRATEGY_SPEC.md) for the authoritative specification.
